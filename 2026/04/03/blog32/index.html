HTTP请求走私

原理

如今web应用程序通常在用户和最终应用程序逻辑之间部署一系列HTTP服务器。用户向前端服务器（有时称为负载均衡器或反向代理）发送请求，该服务器再将请求转发到一个或多个后端服务器。

当前端服务器将 HTTP 请求转发到后端服务器时，通常会通过同一个后端网络连接发送多个请求，因为这样效率更高，性能更好。该协议非常简单：HTTP 请求一个接一个地发送，接收服务器必须确定一个请求在哪里结束，下一个请求在哪里开始。

在这种情况下，前端和后端系统必须就请求达成一致。否则攻击者利用前后端对请求解析不一致，构造恶意请求，从而达成HTTP 请求走私

漏洞成因

HTTP/1 规范提供了两种不同的方式来指定请求的结束位置：Content-Length标头和Transfer-Encoding标头

Content-Length头指定了正文的长度

Transfer-Encoding头可用于指定消息体使用分块编码，\r\n作为分隔符，长度以16进制表示,消息以大小为零的数据块结束

当一个请求同时包含了这两个头部，RFC 2616规范 TE的优先级更高，不过在现实中却存在五花八门的形式

  • CL.TE：前端服务器使用Content-Length标头，后端服务器使用Transfer-Encoding标头。
  • TE.CL：前端服务器使用Transfer-Encoding标头，后端服务器使用Content-Length标头。
  • TE.TE：前端服务器和后端服务器都支持该Transfer-Encoding标头，但可以通过某种方式混淆该标头，使其中一个服务器不处理该标头。

(Content-Length把\r\n当成两个字节,Transfer-Encoding把\r\n当作标记)

CL.TE 漏洞

这里，前端服务器使用一个Content-Length请求头，后端服务器使用Transfer-Encoding另一个请求头。我们可以构造一个HTTP请求走私

前端服务器处理Content-Length，确认请求体长度为 13 字节，3+2+8，刚好读取完。

后端服务器处理Transfer-Encoding头部信息，读到0\r\n就认为结束，那么后续的SMUGGLED则不予处理，后端服务器会将它们视为序列中下一个请求的开始

TE.CL 漏洞

前端服务器使用一个Transfer-Encoding请求头，后端服务器使用Content-Length另一个请求头

前端服务器处理Transfer-Encoding头部信息，因此会将消息体视为分块编码。它处理第一个数据块（长度为 8 字节），直至下一行的开头SMUGGLED。然后，它处理第二个数据块（长度为零字节），并将其视为请求的终止符

后端服务器处理Content-Length请求头，并确定请求体长度为 3 个字节，直到 之后的行的开头8。接下来的字节（从 开始SMUGGLED）将不予处理，后端服务器会将这些字节视为序列中下一个请求的开始

要使用 Burp Repeater 发送此请求，您首先需要转到 Repeater 菜单并确保“更新内容长度”选项未选中。

您需要\r\n\r\n在最后一个句点之后添加尾随序列0。

TE.TE 行为：混淆 TE 标头

前端服务器和后端服务器都支持该Transfer-Encoding标头，但可以通过某种方式混淆该标头，使其中一个服务器不处理它

构造方式 原理 / 目的
Transfer-Encoding: xchunked 某些后端服务器在解析时只检查字符串是否“包含” chunked，而前端可能要求精确匹配。
Transfer-Encoding : chunked 在冒号前加空格。有些解析器会忽略这个空格，有些则会认为这是一个无效的自定义 Header。
Transfer-Encoding: chunked Transfer-Encoding: x 发送重复的 Header。前端可能只看第一个，后端可能取最后一个（或者相反）。
Transfer-Encoding:[tab]chunked 使用制表符（Tab）代替空格。RFC 规范允许，但某些不严谨的解析器会将其视作非法字符从而忽略该 Header。
[space]Transfer-Encoding: chunked 在 Header 行首加空格。这被称为 Header Folding（旧规范允许，新规范已废弃）。后端可能会将其拼接到上一行。
X: X[\n]Transfer-Encoding: chunked 注入换行符（CRLF 注入）。利用某些服务器对 \n 或 \r 处理的漏洞，强行在 Header 区域“切出”一个新的 Header。
Transfer-Encoding: : chunked 故意折行。后端解析器如果支持折行处理，会将其合并为完整的 Header，而严格的解析器会报错或忽略。
