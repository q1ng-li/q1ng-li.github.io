栈帧逃逸

栈帧逃逸之前碰过，这里我想通过一些题目来表示

CISCN 2024 mossfern

我们简单分析一下源码的拦截手段

首先第一层是源码字符串静态检测，过滤了 ["__", "getattr", "exit"]并且必须是ascii字符，之前利用Unicode绕过的方法行不通

其次第二层检查运行过程的状态，利用一些钩子函数，防止代码运行过程中出现 ["marshal", "__new__", "process", "os", "sys", "interpreter", "cpython", "open", "compile", "gc"]

最后是检查字节码，字节码中不能存在 "LOAD_GLOBAL(加载全局变量/函数)", "IMPORT_NAME(导入模块)", "LOAD_METHOD(加载方法)"

这里是我们code运行的环境，可以看到__builtins__被置空，只留下了randint,randrange,seed,print这几个函数。首先一定是要逃逸出这个pool box

在Python中，想要拿到栈帧，通常有两条路：

  • 利用sys._getframe()，这需要导入sys，还需要调用函数。

  • 利用生成器对象，这时Python的语法特性。

def f():
yield g.gi_frame.f_back

是一个生成器定义函数，返回 栈帧 f() <frame at 0x000001BE47450580, file ‘stack.py’, line 3, code f>

在文章[利用生成器栈帧逃逸 Pyjail | CISCN 2024 mossfern 题解](https://www.pid-blog.com/article/frame-escape-pyjail#没想到的解法)末尾，作者提及到这个exp是否是多回溯了一次？

其实这里还有一个细节，frame=[x for x in g][0]这个列表推导式也会创建一个隐式的函数，如果直接打印frame就是<frame at 0x0000020C55BB81F0, file '<sandbox>', line 5, code <listcomp>>所以frame.f_back才会回到getflag(), frame.f_back.f_back回到<frame at 0x0000020F7F3C9110, file '<sandbox>', line 7, code <module>>即exec函数运行的环境,最后frame.f_back.f_back.f_back就成功逃脱沙箱

对于最后读取flag,由于审计钩子过滤了open等读取flag的函数，这个exp中利用了f_code获取了主程序的代码对象，这个对象中的co_consts方法是代码对象中存储的所有常量，但不能出现THIS_IS_SEED，所以可以选择逐个打印出

这个写法有问题，如果发现code中存在 [“randint”, “randrange”, “print”, “seed”] 函数就直接break,跳出opcode的检查。那是不是意味着我在开头触发，后续就允许字节码出现["LOAD_GLOBAL", "IMPORT_NAME", "LOAD_METHOD"];不过重要的是，一开始不能触发if any(x in str(line) for x in ["LOAD_GLOBAL", "IMPORT_NAME", "LOAD_METHOD"]),所以可以利用 LOAD_NAME,

不过最有趣的还是劫持os._exit

这里将print函数替换为w_print函数，而在w_print函数则将os._exit替换为了print函数；也就意味着后续如果遇到print函数就会触发w_print(v)，os._exit(1),就会变成print(1),程序就不会退出。
