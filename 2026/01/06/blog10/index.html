题目给的服务端源码

结合wp,pdfminer库函数下的cmapdb.py中存在漏洞（CVE-2025-64512）

由于之前的漏洞已经在原作者的代码中进行了patch,这里的版本是pdfminer.six==20250506。在_load_data处下个断点。

构造的pdf如下

说实话，第一次看到这个pdf有点懵，毕竟之前看到的都是经过源码渲染的。简单解释一下这个源码，首先%PDF-1.7是定义pdf规范；接着1 0 obj 表示第一个对象，定义了一个目录（Catalog）,以及引用了页面对象（通过/Pages 2 0 R）；endobj表示结束；后面其余对象分别定义了字体，大小等等；最后，xref(交叉引用表) 定义了每个对象在文件中的字节偏移量（例如 0000000010），trailer指出根对象是 1 号对象，并包含文件结束标记 %%EOF。

可以看到成功调用了_load_data，传入的参数是Adobe-GB1-0。name=”Adobe-GB1-0”,接着去除空字节，filename=”Adobe-GB1-0.pickle.gz”,系统环境变量 CMAP_PATH 指定的路径，或者默认的 /usr/share/pdfminer/;接着进入for directory in cmap_paths循环，假设directory是/usr/share/pdfminer/，path拼接为/usr/share/pdfminer/Adobe-GB1-0.pickle.gz，一旦找到文件，就先利用gzip打开文件，再将文件内容进行反序列化。那么接下来我们就要控制pickle文件的路径 ，可以看到源码中没有对name进行过滤，那么我们可以利用目录穿越，比如/Encoding /../../../../../../../../../../../evil来控制路径，但是.和/不会被当成字符串，那么就配合16进制进行编码 /#2e#2e#2f#2e#2e#2f#2e#2e#2f#2e#2e#2f#2e#2e#2f#2e#2e#2fapp#2fa 首先解释一下，第一个/表示界定符，后面的#2f是因为PDF ISO 32000 标准明确规定，Name Object 的十六进制转义符只能是 #

发现成功实现目录穿越

调用堆栈

这里成功调用了_load_data,根据调用堆栈，我们好好代码审计一下(这是关键)

按照堆栈调用顺序，首先我们来看看get_cmp()函数的逻辑，这里的name = ‘UniGB-UTF16-H’,那么肯定我们需要知道name的值的来源，先将get_cmp()搁置此处，我们继续往上扒；看到get_cmap_from_spec()

此处的cmap_name又是从_get_cmap_name()传来的，先将get_cmap_from_spec()搁置，继续向上扒；可以看到_get_cmap_name的形参类型，spec: Mapping[str, Any] ,这是一个映射（字典），键（Key）是字符串，值（Value）可以是任意类型.

pdf源码中的结构

spec的内容就是 映射出来的python字典

可以看到cmap_name=spec[“Encoding”]。此刻我们知道了name的来源，就是/Encoding 后面的值；为了调用链的完整连接，我们继续往上看。我给spec变量添加上了监视，方便看到其生成过程，终于在/pdfminer/pdfinterp.py下的PDFPageInterpreter下的init_resources ,即404行命中断点，此时的spec还不是字典。

在调用堆栈init_resources会调用get_font,我们这次回头看看

可以看到如果想要继续向上完成调用链，就要满足235行，subtype == “Type0”,这里我的构造是成功的；接下来还是调用这个函数

需要满足subtype in (“CIDFontType0”, “CIDFontType2”) ,也就是说满足字体类型为复合字体。符合条件就会调用PDFCIDFont类,触发构造函数__init__，在这个构造函数内部

成功调用了get_cmap_from_spec()。那么至此后半部分调用链就完成了闭合。现在我们往前看，前面的调用链似乎都是固定操作，似乎没什么问题，那么调用链应该就完成了闭合。

接下来我们的任务就是要上传一个即符合pdf格式，还能被gzip解压的文件。先随便上传一个文件，题目给出提示

这是一个可以通过pdf检测的简单源码

查阅官方wp，发现gzip压缩实际上也是支持注释的，如果我们把上面的通过pdf检测的源码作为注释，不但可以绕过pdf检测，在解压的过程中也不会干扰data解压，官方的payload是利用检测时只检测是否存在这个漏洞来绕过，具有局限性

“Polyglot” (多语言/多格式混合)攻击

查阅了别的队伍(Polaris)的payload,技术含量更高的payload

我们一点一点来看，首先build_pdf函数中就是生成一个pdf;build_gzip_with_extra函数利用了FEXTRA（拓展字段），Gzip 标准规定：解压程序在读取到 FEXTRA 标志时，会读取长度字段，然后跳过指定长度的数据（即跳过整个 PDF），直接去解压后面的data。当然，本质上与官方的原理相同。
