信息收集

首先还是利用nmap/dddd等工具信息收集一波

切入点

对于cgi-bin文件后续的利用没有头绪，于是去学习wp

在wp中，我们发现在处理这两个不同路径的文件时利用的是不同的服务器，那么这个时候可能会想到利用这两个服务器处理的差异可不可以实现一些操作?继续学习wp思路

上面我们对/目录进行扫描没有发现什么，作者于是乎对/page/目录也进行扫描。在目录扫描时发现了index.php

有个有意思的地方，我们访问/page/index.php得到的是raw数据，而不是经过执行后的php内容，随后发现 /page/index.php?page= ，无论如何构造都无法拿到想要的页面。随后了解了readfile这个函数，

我们不妨尝试访问/page/test

我们发现test竟然作为了参数传递给了readfile,那么也就好解释之前的疑问的地方。那么我们接下来利用这个点来进行一些文件读取。测试过程中发现url双重编码来绕过一些限制

请求走私

正如我们上面提到的两个不同的服务器，我们在这里可以对网站运行机制做一个假设。当我们与前端apache/2.4.55进行交互时，当url以/page/开头时，服务器会提取后面的内容，将请求代理到后端的apache/2.4.54服务器，该服务器有gen.php和index.php,作为uhttp://backend:8080/index.php?page=的参数。

然而我们可以利用readfile()函数，它允许我们使用各种协议（http,ftp）等协议读取资源。进而完成ssrf漏洞

可以看到我们成功请求到后端的gen.php，响应结果提示我们输入length参数

对于上述前后端交互方式，我们通过搜索发现与mod_proxy代理模式很类似，通过搜索 Apache v2.4.55 related to mod_proxy，发现CVE-2023-25690,CRLF漏洞。

mod_proxy 是 Apache HTTP Server 的一个核心模块

为了方便理解，我们举个例子

经过代理，后端接收到的就变成两个请求

利用上述方式，我们可以构造恶意请求，达到getshell的目的

在两个主机的80端口，都是我们之前已经getshell的服务。可是在172.18.0.1:5000端口是一个新的web服务
